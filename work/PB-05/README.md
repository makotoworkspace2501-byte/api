## Что отвечает по-настоящему

| Сценарий | Метод и путь | Файл и функция | Код успеха | Коды отказа |
|---|---|---|---|---|
| Отправка вычислительной задачи на балансировку | POST /api/v1/processes | main.py: create_process | 202 | 401, 422, 503 |
| Чтение статуса или результата задачи | GET /api/v1/processes/{task_id} | main.py: get_process | 200 | 403, 404 |

## Где лежат данные

Словарь в памяти, пропадает после перезапуска: да. Фильтр по владельцу (X-Api-Key) добавлю в ПР № 9.

## Повтор
Проверка заголовка `Idempotency-Key` в функции `create_process`. Если ключ уже присутствует в словаре `idempotency_cache`, функция немедленно возвращает ранее созданный `task_id` и его статус, не создавая новую запись в `processes` и не запуская вычисления повторно.


## Коллекция на порту 8000

| № | Имя в коллекции | Ожидаю | Факт от сервиса | Комментарий |
|---:|---|---|---|---|
| 1 | Создание задачи (успех) | 202 | 202 | Возвращает task_id и status: processing |
| 2 | Повторное создание с тем же Idempotency-Key | 202 | 202 | Возвращает тот же task_id, эффект не применён дважды |
| 3 | Чтение существующей задачи | 200 | 200 | Возвращает данные задачи |
| 4 | Чтение несуществующей задачи | 404 | 404 | Единый формат ошибки |
| 5 | PATCH статуса завершённой задачи | 409 | 409 | Без заголовка Prefer, так как это не мок |
| 6 | Чтение списка задач | 200 | 200 | Ключи появятся в ПР № 9 |

## Две проверки curl

# 1. Успешное создание задачи
curl -X POST "http://127.0.0.1:8000/api/v1/processes" \
-H "X-Api-Key: test-key" \
-H "Idempotency-Key: unique-123" \
-H "Content-Type: application/json" \
-d '{"task": "compute"}'

# 2. Попытка повторного создания с тем же ключом (должна вернуть тот же результат)
