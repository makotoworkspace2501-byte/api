## Таблица операций

| Сценарий | Метод | Путь | Код успеха | Код отказа |
| --- | --- | --- | --- | --- |
| Успешная маршрутизация / Ошибки валидации и аутентификации / Отказ нод | POST | `/api/v1/processes` | 202 | 400, 401, 503 |
| Чтение одной вещи по номеру (результат или статус процесса) | GET | `/api/v1/processes/{task_id}` | 200 | 403, 404 |
| Получение списка задач (пагинация) | GET | `/api/v1/processes` | 200 | 401 |
| Запрещённый переход статуса (попытка изменить завершенную задачу) | PATCH | `/api/v1/processes/{task_id}/status` | 200 | 409 |
| Проверка работоспособности сервиса | GET | `/health` | 200 | - |

## Повтор
Заголовок `Idempotency-Key` передается в методе `POST /api/v1/processes`. Если балансировщик видит этот ключ и задача с ним уже была обработана или находится в обработке, он возвращает предыдущий статус и `task_id` с кодом `202` или `200`, не запуская вычислительный процесс на нодах заново

## Список
Метод `GET /api/v1/processes` поддерживает параметр запроса `?limit=20`. 
*Фраза из требования:* В списке возвращаются только вещи (задачи) владельца этого ключа (`X-Api-Key`).

## События
Событие из строки 8 паспорта: `Node.Offline`.
Поля сообщения (вебхука, который сервис пошлёт наружу в будущем):
- `node_id` (string): Идентификатор упавшей ноды.
- `status` (string): Текущий статус ("offline").
- `timestamp` (string): Время события в формате ISO 8601.
*(Отправка события ещё не программируется, только описывается).*

## Совместимость
**Что можно добавить, не ломая старых клиентов:**  
Новое необязательное поле в теле запроса `POST /api/v1/processes`, например, `"priority": "high"`, которое балансировщик может учитывать при расчете весов PSO, игнорируя его, если поле отсутствует.

**Что уже нельзя менять в v1:**  
Переименование поля `task_id` (например, в `process_id` или `job_id`) или изменение смысла значений статуса (`active`, `degraded`, `offline`, `completed`). Это потребует создания версии `/api/v2`.
